## 四、输出尺寸：跟随输入图，按 32 对齐（不是漂移）

初版本文件写“尺寸漂移”，**结论错误，已更正**。工作流接线如下：

```
459:468 ComfySwitchNode   switch = False
         on_false = 459:474 的第 3 个输出   ← 参考图编码出的 latent（实际走的这条）
         on_true  = 459:456 EmptyLatentImage ← 接在 ResolutionSelector 上，被旁路
```

`ResolutionSelector`（9:16 / 1.0 MP / multiple 32）**不参与出图尺寸**。实测 10/10 全部等于「输入图尺寸按 32 对齐」：

| 图号 | 输入尺寸 | 输出尺寸 |
|---|---|---|
| 446 / 449 / 454 / 455 / 472 / 473 / 474 | 1200×1600 | 1216×1600 |
| 453 | 1200×2124 | 1216×2112 |
| 466 | 1200×1200 | 1216×1216 |
| 470 | 614×612 | 608×608 |

**结论 3 修正**：要固定尺寸只有一条路 —— **把输入图本身做成目标尺寸**；在 `ResolutionSelector` 上改数值无效（被 switch 旁路）。
仍成立的推论：尺寸不同的两张图不得互比像素（这条与漂移无关，是降采样污染，参见换脸 00363/00367 旧结论作废的教训）。
