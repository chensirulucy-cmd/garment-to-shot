本报告替代此前将拆图拼接作为建议的分析。四视图永久排除分别生成后拼接，保留 478 服装板 → 515 一次生成完整四视图。19 张给定样本已读 PNG 元数据并核对文件 SHA256；18 张原始生成图有完整 prompt 图，00416_headless 无。六张成功案例按用户确认保留，00426 明确失败。原图未修改，本轮没有调用生成模型。

## 一、已经查明与尚未查明

**查明的是证据链和提示词的结构缺口，尚未证明唯一的出图根因。** 不能再写“必然是连身裙”“同种子随机”“反引号导致槽位断开”，也不能把侧面无头直接等同于已经定位了模型内部注意力分叉。

角色分支只有一个 TextEncodeQwenImage21（515:513）、一个 KSampler（515:510），没有给正、背、侧面分别编码的节点分支。旧正向先说“改变头和衣服”，然后把正、背、侧面串在一句中，直到侧面后才统一追加 each of the three … no head。其后又要求从头肩肖像取得 body build、height、hands，而这张参考图没有全身和手。前三格身体几何应以画布为依据；第四格脸身份才由肖像承担。

另一个具体缺口是把身体上边界写成 collar of the garment closing the top edge。吊带裙领口低于肩部，领口不能代替肩线；把“上方清空”做成“沿服装领口清空”会威胁肩部和手臂。这是文本与目标不一致的证据，不是已证实的模型因果机制。00426 的实际图像说明只验“没有头”会误收一个缺肩、缺臂、缺手的结果。

优先待检验假设：将无头约束明确分配到每一个站立视图，同时明确保留肩、臂、手和画布体态，可减少整个人像补全及身体删除。R1 只验证这一块，不能把其中每个词分别宣称有效。00410→00411 只换画布就让侧面也冒头，证明输入空间构图同样能改变结果；不能先排除画布因素。

## 五、Muse 遮罩思路与 JSON 审查

**在一次整图生成过程中保护指定背景区域，原则上可行；现有 JSON 还不能直接证明可运行，更不能保证永久没有头。** 它没有真正的“布图层”，也没有生成后揭布的节点。519 是原画布 VAEEncode，520 读取 mask，521 把 noise_mask 送入角色采样器。这是采样区域约束。

本地源码中 KSamplerX0Inpaint 用 mask=0 的区域保持原 latent，mask=1 的区域允许生成；这是空间约束，不依赖模型是否听懂 no head。所需 mask 应只保护前三格肩膀以上的原背景，保留肩部、上胸、臂、手、衣服及第四格作为可生成区。绝不能按“衣服领口以上”一刀切，也不能固定裁掉顶部 17%。

现文件的问题：

1. LoadImageMask（520）缺少必填 channel。alpha 通道使用 1-alpha；red 通道直接取红值，所以同一黑白图配错通道会反向或全锁。
2. headzone-mask-v3-alpha-fixed.png 在已检查的 Downloads 与 ComfyUI input 中不存在。缺少它就无法检查边界、极性、肩部保护是否正确，不能假装已验收。
3. 新 519 直接编码 2075×1184 画布；本地 Qwen VAE 的 16 倍压缩使中心裁切得到 2064×1184，而文本编码参考图路径取整成 2080×1184。必须先统一整张画布、参考和 mask 的尺寸坐标，不能把两条路径的坐标默认等同。
4. JSON 基于早期黑上衣白裙与上游 LoRA 生成人像，并大幅重写两支提示词，不是本轮吊带裙的单变量实验。不要拿它的输赢判定 R1。
5. noise_mask 锁的是 latent；VAE 编解码和边界插值不保证原始背景逐像素相同。头发落入可生成区、把头挤到保护区下方等仍需检查；保护顶部本身不等于语义上的绝对无头。

因此自定义节点可以封装整图对齐与保护遮罩，保持一次生成、无需增加手工拼接步骤。但当前先跑提示词 R1；若仍失败，再在同一基线上验证保护遮罩。缺少的 mask 必须先取得，不能凭文件名推定正确。未安装插件、未修改本地 ComfyUI、未提交 GPU 任务。
