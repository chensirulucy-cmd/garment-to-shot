# Qwen-Image 编辑合成：人物 + 服装 + 场景 → 一张成品照

**这是一条独立任务线**，与「服装模板 / 人像 / 四视图」那套资产流水线（`character-asset-pipeline`）不是一回事：资产流水线产出**可复用素材**，本 skill 把素材**合成成一张成品照**（她在某场景里、穿某套衣服）。合成类问题只用本 skill 的规则回答——别拿资产规则来套合成任务，也别把合成规矩塞进资产任务。

## When to Use

- 用户给了 2–3 张参考图（身份图 / 服装图 / 场景图），要「她穿上这套衣服、出现在这个场景里」。
- 用户抱怨合成图「脸不像 / 有合成感 / 不像真拍的 / 人漂移了」。
- 用户要先出一张静帧，再拿去 H3 参考图生视频（本 skill 是上游）。
- 不适用：单图改色改风格、纯文生图、资产流水线（那套走 `character-asset-pipeline`）。

## 三槽分工（先定好再写提示词）

| 槽 | 图 | 唯一作用 |
|---|---|---|
| `<image1>` | 面部特写 / 身份图 | **身份**：脸、发、肤色、体格 |
| `<image2>` | 服装图 / 服装板 | **服装**：件数、设计、颜色、材质、细节 |
| `<image3>` | 场景图（空景或带人） | **画布**：构图、机位、光、家具、道具一律保留 |

- 规范口径是「画布 = 场景图」；但**这套编辑节点在 `custom_size=false` 时输出尺寸跟随 `<image1>`**（实测：第 1 张 832×1216 → 出图 832×1216）。要画幅跟场景走，就把场景图放第 1 槽，或开 `custom_size` + ResolutionSelector 指定。
- 三张图比例一致最省事；不一致时模型会重排构图。
- 第二刀（质感统一 / 只修脸）：`<image1>` = 上一刀成品图，`<image2>` = 身份图。

### 写提示词前：先把接线抽出来（必做，比措辞重要一个量级）

`<imageN>` 是**提示词里的序号**，不是工作流里的槽位。导出的 API 格式 JSON 里，`TextEncodeQwenImage21` 的 `images.image_1/2/3` 接的是上游节点，谁接谁只有打印出来才知道：

```python
import json
d = json.load(open(workflow_json, encoding="utf-8"))
def upstream_images(nid, seen=None):
    seen = set() if seen is None else seen
    if nid in seen or nid not in d:
        return set()
    seen.add(nid)
    n = d[nid]
    if n.get("class_type") == "LoadImage":
        return {(nid, n["inputs"].get("image", ""))}
    sources = set()
    for value in n.get("inputs", {}).values():
        if isinstance(value, list) and len(value) == 2 and isinstance(value[0], str) and isinstance(value[1], int):
            sources.update(upstream_images(value[0], seen))
    return sources
for nid, n in d.items():
    if n.get("class_type") == "TextEncodeQwenImage21":
        for key, edge in n.get("inputs", {}).items():
            if (key.startswith("images.image_") or key.startswith("image_")) and isinstance(edge, list):
                print(nid, key, "direct edge:", edge, "upstream dependencies:", sorted(upstream_images(edge[0])))
```

- 脚本报告直接上游与所有LoadImage依赖；生成式上游可能依赖多张图，这些依赖不等于当前槽直接输入的成品图。提示词槽序以编码器实际输入为准。
- 典型错位：实际 `image_1`=人台/身体、`image_2`=**人像**、`image_3`=服装，而提示词按「image_2 = 服装」写 → 模型从人像里找衣服，找不到就把那个人整块抹掉，服装反成孤儿槽。症状：**主体部位莫名消失（头/手/脚被截）+ 服装大形对、细节全虚 + 改提示词怎么写都没用**。
- 先核目标任务，再令提示词与真实槽位一致。不能只为适配旧示例而自动断开用户参考图；多输入时记录每个槽的实际职责。
- 一槽一张图，槽里不放四联排/带版式的素材（版式会被搬进结果）。
- **身体可以不是人**：无五官的**关节白模**当 `<image1>` 时没有脸要保，像素全给布料 → 这是把「服装正确值」坐实的标准做法（两段式：先白模验衣服，定稿后再换真人）。白模必须有头，无头会顺着 ghost-mannequin 的电商先验把头砍掉。

## 铁律（第 1 条是这条线上最贵的一课）

1. **先量有效脸部像素，再检查身份结果**：历史通用参考编辑曾出现小脸漂移；线性0.5仅是该路线经验，不是所有模型的成功门槛，尤其不能用来否决已成功BFS配方。
2. **取景与分辨率是两个独立杠杆**：中近景（腰以上）把脸占比从 9–15% 拉到 30–40%；输出提到 2.2 MP 让细节有像素可落。两者可叠加。
3. **服装需独立验收**：服装约束来自 `<image2>` 的约束（件数/设计/颜色/材质 + 禁止重塑/换色/拆分）提供要求，仍受整图生成影响。脸不像时不要无依据改服装段。
4. **要保留的写粗，要改的写细**：把保留物逐项描述 = 给模型下「重画」指令；用一句总括保留句 + 按**类型与位置**点名，不描外观。
5. **身份用「指图」不用「写字」**：用文字复述五官会让模型重画并降低相似度。
6. **cfg > 1 负向才生效**（cfg=1 时负向权重为 0，等于白写）；作者口径是 **cfg 3.5 / steps 30 / euler / simple**。
7. **编辑模式格式**：单段、以动作开头、肯定陈述；比例/像素只进尺寸字段，不写进正文。
8. **8 GB 卡的安全区**：参考图长边 ≤1280、单张 ≤1.5 MP，**输出 ≤2.2 MP**。9 MP 出图 = 每步数十秒到分钟级、看着像卡死，而且**重启进程无效**（问题在任务数据量，不在进程状态）。
9. **交付即整段可粘贴**：给完整正向 + 负向，不给「改哪几句」的 diff。

## 跨镜身份一致性（同一人出现在 N 个镜头）

1. **全片只有一个身份源**：选定一张脸最大最正的图当所有镜头的 `<image1>`；不要让几套机制各自生成「她」。
2. **星形，不要链式**：每镜都「锚图 + 本镜服装/场景」重新合成一次；**绝不把上一镜的成品当下一镜的输入** —— 链式让漂移逐镜累积，越靠后的镜头越换人。
3. **按实际LoRA用途区分机制**：人物训练LoRA与身份图同时输入可能存在竞争，但不能写“混用必得两张脸”。00373的Pruna+BFS与两张参考图是本仓库已用配方，BFS是专用换头编辑LoRA。
4. **像素估算只作构图诊断**：若暂用输出脸高≥锚图脸高/2这一经验条件，则输出画高≈锚图脸高/(2×脸占画高比例)。例如300/(2×0.30)=500；比例0.09时约1667，1920高在算术上足够。0.5本身未经跨路线验证，不据此降低参考脸质量或宣称身份必然稳定。
5. **文字能不能复刻服装：先分级再选线**（详表见 `qwen-image-2-1-prompter/references/garment-from-text.md`）：**AI 生成的服装**（原型本来就是文字，例如自家工作流出的产品图）→ 文字**结构级神似可用**（非件件对齐）；**真实拍摄的纯色结构款** → 同款级；**印花 / 条纹 / 渐变 / 特殊纹理 / logo** → 必漂，只能拿服装素材图当 `<image2>` 走编辑链。文字线的常态是**神似但不件件对齐**（典型漂：领型被简化、两侧装饰被合并到中部、可见细节变少）→ **展示镜与氛围镜可用文字线，「货对版」的商品特写必须走编辑链**。反推出的服装提示词另有三个正当用途：写进编辑提示词的**服装约束句**；用在不需要精确复刻的镜头（备选/远景/氛围）；当 A/B 对照。
6. **判「像不像」要量化，不要凭眼睛**：人脸用 ArcFace 余弦相似度（SCRFD 检脸 + w600k_r50 特征，阈值 0.5–0.6 起调，导出 CSV 再人工复核）；服装按四条打分 —— 件数 / 主色 / 材质纹理 / 结构细节（领型、袖型、裙长）。本机现成脚本、模型摆放位置与 A/B 判读法见 `references/identity-scoring.md`。
7. **多镜架构先做 A/B 再定**：① 编辑星形 N 镜 ② 编辑链式 N 镜 ③ T2I+LoRA N 镜 → 比各组**内部两两相似度**，取一致性最高那组当全片架构。
8. **发型是最容易漂的身份元素**：模型会按自己的审美惯性换发型（束发→披发最常见），**即使提示词已经写了「发型照图复刻」也照漂**。写法要落到颗粒度 —— 束在哪儿、鬓边与额前碎发的位置、头发垂在肩前还是肩后；再把漂移形态（披散 / 放长 / 换发型 / 无束发）逐个写进负向。任何一镜出来先看发型，它是身份是否还在的第一指示器。

## 流程（顺序别反）

1. **量三样**：`<image1>` 的像素与脸占画面比例、目标输出的像素与脸占比 → 算线性比。比值偏小时记录风险，结合实际路线和结果判断，不套用到BFS。
2. **合成**（基础版或自然化版，成品提示词见 `references/composite-prompts.md`）。
3. **自然化**（合成感重时）：只由场景的窗光照亮 + 接触阴影与体重感 + 发丝融合 + 同一层景深 + 皮肤不磨皮。
4. **质感统一刀**（备用，未实测）：保留结构只改光与质感，专削合成感。
5. **只修脸刀**（备用，未实测）：脸还差时用，其余全部保留。
6. 要出大图放到**放大阶段**做（SeedVR2 一类），不要让扩散直接在 9 MP 上跑。

## 合成感的九条来源 → 对应写法

| 看图能看到的现象 | 写进提示词的对应句 |
|---|---|
| 脸部像正面柔光箱，与窗光冲突 | 只由场景里的窗光照亮、同角度同色温；无 studio key / softbox / frontal fill / rim light |
| 发丝太齐、边缘生硬或光晕 | 发丝成缕与背景融合、个别飞发、no cut-out line、no halo |
| 脸、桌面、远景全都清楚 | 与场景同一层景深，背景按场景自身柔度衰减 |
| 椅面/桌面/器具下无阴影、人像浮着 | 体重压椅面、前臂接触阴影、脚下与椅底阴影、器具各有自己的接触阴影 |
| 皮肤磨皮、衣物无纹理 | 自然肤质与可见毛孔、不做美颜；针织纹理+褶皱+厚度、皮革颗粒、金属高光 |
| 双手被裁掉或藏起来 | 下缘切在裙腰以上、不切手掌与手肘；双手在桌面、手指清晰分开且数量正确 |
| 背景物件被重画（笔电像板、杯把不清、植物简化） | 明确「场景是画布」；玻璃要有室内微弱反射 |
| 像素不足 → 细节无处落 | 输出 2.2 MP |
| 三个来源光向/质感不同源 | 提示词压不动的部分：靠质感统一刀 + 放大阶段 |

## 下游：H3 参考图生视频（上游图对了才稳）

- 图片标签是 **1-based**：ComfyUI 界面可能显示「图片0 / 图片1」，提示词里必须写 `<Picture 1>` / `<Picture 2>`（内核注释：*Ordinals are 1-based per type*）。**`<Picture 0>` 不是真标签，会被静默丢掉**——场景可能还对，身份却对不上。
- 静帧里**已经有人**，就当**真首帧**用（`summary` 里写 `keyframe completion`）：位置与尺度印在图里 → 不会站位漂移。
- 两种漂移分开治：**站位漂移** = 缺帧锚（参考图里没有人）；**相似度漂移** = 脸的像素预算。措辞极少是原因。
- 完整的 H3 六段式规则走 `minimax-h3-video-prompt`（用户自有 skill，本 skill 不重复它的规则）。

## Pitfalls

1. 只顾「输出跟输入图走」而没量那张输入图多少像素 → 一张 9 MP 参考图把输出顶到 9 MP，跑一小时像卡死。
2. 只在提示词里找「脸不像」的原因 → 第一变量是脸在输出里的像素量（取景 × 分辨率）。**并且先读保存节点标注的实际输出尺寸**：编辑节点可能只出到 ~0.6 MP（实测出现过 576×1024，脸只剩锚图的 0.53×）。典型的「分辨率不足」症状组合 = **脸大致像但细节不够 + 手/包带等小物件糊 + 场景里的文字压不干净**；出现这个组合就把尺寸控件（ResolutionSelector 的 megapixels 等）提到目标值重跑，而不是改措辞。
3. 为了脸牺牲整套服装（其实两者独立）→ 改用「出两张」或「全身 + 只修脸」。
4. 拿资产流水线的规则答合成问题（两条任务线不能混）。
5. 用黑边补比例 → 模型会把黑边抄进画面；用原图背景色补边。
6. 判断「变快了没有」只看感觉 → 看 GPU 利用率（长期 <20% 且显存钉在 7.9 GB = 在换页）与日志里的 `s/it`。
7. 单图编辑把人物放进新场景时，**原图的衣物与道具会跟着过去**（T 恤、手机、沙发、茶几）→ 负向必须**逐项点名这些具体东西**（泛词 `no extra objects` 挡不住）。单图换景的验收固定三条：① **还是同一个人**（脸型 / **发型** / 体格）② **零泄漏**（原图的穿着、道具、家具一个没有）③ **场景自洽**（脚踩在地面上、有接触阴影、光向与影子一致）。三条里只有第 ① 条需要动提示词/收口刀，②③ 是负向与画布的活。

8. **负向写「特征级」词会把整块区域推走**：为了防「长出五官」而在负向里堆 `eyes, nose, mouth, lips, eyebrows, eyelashes, hair, wig, skin tone` 时，模型最省事的满足方式是**把整个头删掉**（白模变无头）。负向只写形态/件数/材质/位置（`headless, severed neck, cropped head, hollow neck`）；要空头就**正面描述形态**（`a smooth white head, egg-shaped, matte resin, continuous from crown to jaw`）。同理，正向里不要出现 `headless / no face / empty neck opening` —— 需要该部位存在时，这些短语等于下删除指令。一次只加一组负向词，出问题再加。

9. **归因顺序：接线 → 尺寸 → 像素预算 → 提示词**。「结果没变」时先跑上面那段接线脚本，再读保存节点的实际输出尺寸（实际latent分支被选中时相应尺寸设置才生效）；这三步能从 JSON 和元数据直接读出来，比反复改措辞快得多。比例类的抱怨（腿短、肩窄、脚小）几乎总是**提示词里没给数字**，而不是模型不会：写死 7.5 头身、肩 2.35 头宽、腿占身高 47%、脚长≈头长、相机腰高 85mm @3.5m、人占画幅 90%。

## 反向清单与颜色分离（来自 00315 元数据）+ 上身失败的结构性根因（00319）

- **「不带走什么」要逐项写**：`Carry over nothing else from <image2> — not its light-blue shirt, not its model's body, not its background, not its lighting and not its lettering.` 这句治的是「参考图的次要元素渗进来」（衬衫／背景／水印），比笼统的 `keep only the garments` 有效得多。
- **两参考严格分工 + 颜色分离**：`<image1>` 只供上装、`<image2>` 只供下装与鞋；再补一句 `The navy of <image1> reads as a deep navy and the black of <image2> reads as true black, clearly separated, never crushed into one another, both keeping their own sheen and seams.`
- **上身失败样本（A 级观察）的**完整**归因**：早期只记「2 槽 + 没画布」，但逐字抽出工作流接线后，主因是**提示词标签与实际接线错位**（正文说 `<image2>` 是服装，实际那里接的是人像；真正的服装在 `<image3>` 且全文未提）。→ 上身镜先查接线；三槽应为「身体/身份 + 服装 + 画布」，且标签必须与接线逐一对应。没有画布就退到中全景，别赌全身。
- **空白背景墙当第三槽（未验证，待跑）**：没有场景空镜时，可先 T2I 出一张竖幅纯净无缝背景墙（无道具、无字、墙地一体弧）当画布；要让输出尺寸跟它走，就把**画布放第 1 槽**（`custom_size=false` 时输出尺寸跟随第 1 张输入图）。这条尚未实测，别当已验证结论引用。
