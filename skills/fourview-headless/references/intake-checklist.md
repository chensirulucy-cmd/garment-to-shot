# 新服装接入清单（fourview-headless）

本清单供其他 AI 或人工在接入新服装时使用。它只规定步骤和停止条件，不改变 skeleton_515.txt 的固定正文，也不改变已测的 family 文字。

## 0. 先决条件（缺任一项即停止）

- 服装源图：高分辨率原图，不使用约 608 px 的展示图。
- 身份图：同性别、白底证件或清透白底肖像，记录实际文件名。
- 画布：`four-view-shoulder-top-enlarged.png`。
- 服装板：478 阶段输出。515 需要它作为 image3，不能跳过。

## 1. 选择 profile

按顺序判断，第一个满足的条件即为结果：

1. 肩部露肤、吊带或细带 → `strap`（已验证：00491；换款 00512/00513）。
2. 肩部被包住，外层为开襟或 V 开口，内搭可见 → `vneck`（已验证：00485；男装开衫 00507）。
3. 肩部被包住，领口闭合（高领、包领、半拉链高领）→ `round` 的闭合领变体（已验证：00510、00501；拉链或衬衫领细节须加 COLLAR_DETAIL）。
4. 普通圆领短袖（无闭合高领）→ 未验证。标记为“待测”，不得声称通过。
5. 抹胸、露肩复杂结构、连体、外套领型不明 → 未覆盖。停止并交给人工判断。

不能只看“V 形”或“圆领”这些名称，要看肩部是否露肤、包肩衣物的领口是否闭合。

## 2. 填写配置

必填字段：

- `family`：上一步选出的 profile。
- `subject`：`woman` 或 `man`，必须与身份图一致。
- `role.OUTFIT`：从服装板读取每件衣物的颜色、领口、袖长、下装、鞋履。不得复制其他案例的 OUTFIT。
- `role.LOCK`：颜色与形状锁定句，写法参照同族已验证文字。
- `role.NEG_GARMENT`：仅写与本套服装相矛盾的词。
- `role.COLLAR_OBJECT`、`role.SLEEVES`、`role.NEG_COLLAR`：仅闭合领变体需要。
- `role.COLLAR_DETAIL`：服装有拉链、衬衫领等领口细节时必须填写；缺失会导致细节丢失（00500 的教训）。

## 3. 组装与检查

1. 用 `scripts/render.py` 组装 515 和 478 的正负向提示词。
2. 确认输出中没有未填槽位（`{{` 或 `}}`）、没有未知槽。
3. 确认代词与性别一致：女性用 she/her，男性用 he/his。
4. 确认 OUTFIT 中的每件衣物都在服装板上出现过。

## 4. 生成后的验收

按 SKILL.md 的验收范围检查前三格：

- 头颈与头发不得出现在前三格。
- 肩、臂、手必须存在。
- 三格视角正确（正、背、侧）。
- 服装与服装板一致，细节（拉链、白领、颜色）可见。
- 第四格唯一有人像，身份与身份图一致。

任一项不符，记录为失败，并按 failure-catalog.md 查找已知原因。不要靠重复抽图掩盖失败。

## 5. 停止条件

出现以下情况，不得输出“通过”，应标注待测或交还人工：

- 服装板缺完整背面或侧面视图（参见 00506、00508、00511）。
- 选择的 profile 为“待测”或“未覆盖”。
- 身份图未知或与性别不符。
- 任何固定正文被改动（应恢复为 skeleton_515.txt 原文）。
- 服装槽的内容无法从服装板确认。

## 6. 已知陷阱

- 把旧案例的 OUTFIT 直接复制到新服装上（失败记录 8）。
- 只改 NEG 或只改颜色词，而不改锚点（失败记录 10）。
- 用 off-skeleton 写法替代骨架（00498，失败记录 21）。
- 闭合领锚点覆盖了拉链和衬衫领（00500，失败记录 23）。
- 把 00499 当作某个 515 结果的服装板时，应同时记录它被 00498、00500、00501 共用（见 evidence.md）。
