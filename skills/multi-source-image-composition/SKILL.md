# 多来源合成成一张图（画布 + N 个来源）

一类任务：**一张空场景画布 + N 张来源图（服装/商品/角色）→ 一次编辑出一张多格陈列图**
（六格服装展示墙、货架陈列、换装镜头）。
本技能只管**容量上限、位置绑定、丢件处置、来源图选择与核对**；
具体提示词配方属于各模型自己的技能（本机在用户自有的 `qwen-image-2-1-prompter` 与 `character-asset-pipeline` 里，**不在本技能目录**；展示墙配方在 `qwen-image-2-1-prompter/references/garment-showcase-wall.md`）。
配方归配方，容量与故障处置归本技能，两处不要混写。

## When to Use

- 用户要把多张来源图（N≥3）一次性摆进同一张图的不同位置/格子。
- 合成结果出现**重复、丢件、漏件（漏鞋）、某格发糊**，需要定位原因并给修法。
- 要判断“再加提示词还有没有用”，或者什么时候该**减量重跑**。
- 要把跑通的这类流水线固化（要记哪些基线、哪些变量）。

## 执行顺序（四步，别跳）

1. **先单独生成画布**（空场景/空展示位）。不要指望在编辑那一步同时“造场景 + 摆东西”——两件事的失败会叠在一起，分不清是谁的锅。
2. **画布几何先定死**：竖幅里格数 × 格子形状要配画幅（例：9:16 里 `2行3列` 单格是 1:2.5 的细长条，东西进去糊成条；`3行2列` 单格近方形 ≈1:1.1，一套东西正好站得住）。物品尺寸、亮度、相机距离必须在画布阶段定下来，到编辑阶段再改就是整轮重跑。
3. **编辑：逐槽点名绑定**。每个来源点名到具体位置（`<image2>`→左上、`<image3>`→右上……），并显式写三句：**全部来源到场** / **成图里必须是 N 套彼此不同的东西** / **禁止用邻格的东西填空、禁止两套来源合并成一套**。位置 = **接线顺序**，不是文件名。
4. **跑完只核三条**（10 秒）：数一遍是不是 N 个彼此不同 / 每个是不是件数齐（如上衣+下装+鞋）/ 每个是不是跟它的来源图对得上。不合格走下面的处置顺序，不要直接改提示词。

## 容量上限（硬事实）

- 绑定负担 = **来源数 × 每套件数**（6 格 × 3 件 = 18 个物件 + 6 个身份绑定）。**主因是来源彼此撞色/撞款，不是格数**（格数与件数是次要变量）：来源彼此差异够大时 6 格 × 3 件可以一次跑齐；4 格只是撞色调不动时的退路，不要一上手就主动减格。
- 越靠后的格子越容易漏件（典型：漏鞋）→ 件数必须**逐格点名**；“每个都带上鞋”这种总句不够。
- 到顶后**继续加提示词不再有收益**，只会摊薄每条指令的权重 —— 此时要**换变量**（换来源图、换槽位、减格数），不要加字。
- 提示词能挡住的：件数点名 / 不得跨格复制 / 浅色物体与背景的明暗分离 / 物体不压分隔线。挡不住的：超过容量后“某一张被整格省掉”。

## 丢件处置顺序（不要一上来就降格数）

1. **先看是不是“同一张、同一格”反复被丢**：两轮都丢同一张来源图 → 不是随机的容量问题，是**那张图**的问题 → **换掉它或与另一槽位对调接线**（比降格有效得多）；每轮丢的都不一样 → 才是容量到顶，走第 4 步。
2. **同色系相撞是首要机理**：两套同色系/相近款的来源（灰+灰、米+米、浅粉+浅粉、卡其）会被模型**合并成一套**，另一套整格消失，再拿已用过的邻格去填那个空位 —— **现象是“重复”，病因是“丢”**。选来源图时避开同区间撞色（灰 / 米白 / 浅粉 / 卡其算同一区间），替补优先**强对比色**（深蓝、酒红、黑白格纹、条纹、亮色系）。
   **判定撞车要看「主色 + 整套轮廓」两样都像**：同色系但结构差别够大（连衣裙 vs 上衣+半裙）不一定撞；两套同色连衣裙必撞。**鞋与小配件重复不影响**（黑鞋在一张图里出现四五次是正常的）—— 不要把鞋色当成撞车变量去换。撞车时换掉**撞车对里特征较弱的那一张**，替补自带强特征色。
3. **来源图分辨率 = 那一格的天花板**：单张明显小于同批（约 0.9 MP 对 1.95–2.76 MP）会成为“最弱一格”，面料/扣子/细节发糊 —— 替补图优先 **≥1.2 MP**；某格糊了**换图，不要改提示词**。
4. 换图、挪槽位都试过仍丢 → **才降到 4 格（2×2）分两轮**；不要再在 6 格上加词。

**归因纪律**：说「换掉撞色图就好了」之前，先数一数变了几个变量。有一次「换图后成功」的记录里，两轮的正向、负向、步数、cfg、尺寸**逐条相同**，唯一变化是来源图 **和 seed** —— 两个变量同变，只能算「疑似」，不能写成因果。要坐实必须锁 seed、只换那一张；而用户已明确拒绝为证明重跑重量级链路，所以这类结论**如实标「未受控」**就行，不要反复要卡。

## 单格返修（⛔ 2026-10-18 弃用）

~~把成图当画布 + 只喂那一格该有的来源图，提示词写「只重做 X 格，其余 N-1 格与环境完全不动」。~~

**为什么弃用**：生成/编辑都是**整图去噪重建**，提示词只能决定注意力放哪，**不能决定哪块不被碰**。每次重跑连背景带都会变一次，等于换了一张图，验收无法闭环。用户已判定这条不做。

**替代**：**每格单独生成 + 纯合成拼墙** —— 六张成品图 → 裁切 / 对齐 / 排版，全程**不接 KSampler**。改哪格只重跑那格，其余格物理上不在同一张图里，零漂移。

**注意区分**：`00339` 那种「7 张来源一次画出六格」属于**生成式**拼墙（格式与点选已走通），它仍然是整图重建，不能改单格；只有纯合成具备单格可改性。

## 核对“当时到底用了什么”

- 磁盘上的工作流 JSON 可能是**旧存盘**（UI 改提示词/换图/换画布不会落盘）→ 先看 mtime，再交叉验证；要可信状态就请用户保存一次。
- **输出尺寸 = 第 1 张输入图（画布）的尺寸**，用尺寸反推当时的画布是谁。
- 把聊天里贴的图对回 ComfyUI 真名：对候选输出各算 32×32 灰度均值哈希，位相同率最高即同一张。
- 交给用户前把 **真名 + 尺寸 + 各来源图分辨率** 记成一张表。

> 上面三条的完整做法（含均值哈希代码与旧存盘判断）在 `comfyui-model-forensics` 的 **Procedure F**。

## 固化时要冻住的变量

画布图（固定文件名入 `input/`）、三段提示词（画布 / 编辑 / 单格返修，正+负各一份）、
接线表（槽位 ↔ 文件 ↔ 画面位置）、真实文件名与尺寸、各来源图分辨率、回滚基线。
以后换一批东西**只改两处**：换来源图（按接线顺序）＋ 若槽位变了同步改提示词里的槽位名；
画布、骨架句、结构句一个字不动。
